## 🛠️ v3.6.1 — 修复受限环境（含 VPS）下链路1 直连下载失败

### 背景

有用户反馈：把软件跑在一台 IP 未被风控的 VPS 上，用浏览器手动能正常下载专利 PDF，
但软件自动下载始终失败。排查发现并非 IP 被封，而是几个代码级问题叠加导致的。

### 根因与修复

- **Brotli 编码不匹配（主因）** — 链路1 直连的请求头写死了 `Accept-Encoding: gzip, deflate, br`，
  但运行环境未安装 brotli 解码库时，`requests` 会拿到无法解码的乱码 HTML，正则自然匹配不到 PDF 链接，
  于是误判「未找到 PDF 链接」并转浏览器兜底（无显示的 VPS 上又起不来）。
  **本版去掉 `br`**，与服务端 `vps_server/server.py` 保持一致。
- **PDF 真实地址解析更稳** — PDF 真实路径带哈希目录（如 `ad/75/30/...`），无法靠专利号拼接。
  现在**优先解析 Google 官方的 `<meta name="citation_pdf_url">`**，解析不到再兜底扫描页面里的
  `patentimages` 直链。
- **新增 `%PDF` 文件头校验** — 链路1、链路2 客户端、VPS 服务端三处下载后都校验文件头：
  不是真 PDF（如 GCS `NoSuchKey` 报错页、验证码页、乱码）就**删除并判为失败**，
  不再把坏文件当成功保存/计数（链路1 失败时还会继续走 Selenium 兜底）。
- **限流防护小增强** — 顺序下载之间的固定间隔改为带随机抖动，降低被 Google 限流的概率。

### 验证

- 公开号 `US9876543B2` → 下到约 2.5MB、以 `%PDF-1.1` 开头的 PDF。
- 指向不存在的 PDF 地址时，确认坏文件被删除且任务记为失败（而非存下约 385B 的报错页）。
